# OpenGLESScope Database 0.2.0 full audit

## Scope
- OpenGLESScope application producer 0.2.1
- Database submission schema 2 / technicalReport schema 1
- Worker validation, D1 persistence, frontend reporting, security controls and usability
- Khronos OpenGL ES / GLSL ES / EGL registry baselines and Android Display.HdrCapabilities luminance semantics

## Correctness changes
- Replaced the 0.1.x-only producer parser with bounded compatible 0.x semantic parsing.
- Retained the 0.1.17 compatibility floor and rejected future 1.x producers until explicitly reviewed.
- Applied 0.1.24+ metadata checks and 0.1.25+ strict query-evidence checks to 0.2.1 instead of accidentally bypassing them.
- Added a current-producer versionCode check for OpenGLESScope 0.2.1 = 201.
- Added TXT/structured cross-checking for desired max, max-average and min luminance; present numeric TXT values require cd/m².
- Added explicit unsupported-producer error reporting.

## Specification audit
- Khronos current OpenGL ES core remains 3.2.
- Khronos current GLSL ES remains 3.20.
- Khronos current EGL core remains 1.5.
- Android desired HDR luminance metadata is expressed in cd/m²; API 34+ mode-level supported HDR types remain the current Android path.

## Security and robustness
- 2 MiB streaming request bound retained.
- Exact top-level/nested field allowlists retained.
- Recursive sensitive-key and nesting-depth rejection retained.
- Stable canonical JSON SHA-256 report IDs retained.
- Origin-restricted browser CORS, restrictive response headers and HTTPS production endpoints retained.
- D1 account/database pins and parameterized SQL retained.
- No third-party frontend execution or remote presentation dependency introduced.

## Usability and optimization
- Frontend metrics now expose compatible producer range.
- Database version is visible as 0.2.0 while application producer is independently visible as 0.2.1.
- Superseded JS/CSS assets were removed from the release package after reference checks to reduce stale code and package size.
