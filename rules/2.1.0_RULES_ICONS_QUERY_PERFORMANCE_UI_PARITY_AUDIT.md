# OpenGLESScope 2.1.0 rules, icons, query, performance and UI parity audit

## Release identity
- OpenGLESScope 2.1.0 / versionCode 2100.
- Immutable predecessor: OpenGLESScope 2.0.0 ZIP SHA-256 `4502f803444b997e1cc07af58022b67e282325730a554fa2879fec03346a51f5`.
- Production inventory contract freezes 154 predecessor production files and permits exactly three changed production files plus one new production resource.

## Rules parity
- `rules/PROJECT_RULES.md` has exactly one authoritative `# OpenGLESScope Engineering Rules` root.
- VulkanScope 3.0.12 `PROJECT_RULES.md` is preserved byte-for-byte as `rules/VULKANSCOPE_3.0.12_PROJECT_RULES_REFERENCE.md`, SHA-256 `9c89153fb34352f567ccdec7b3685ac1feab56c45b46b22f320375dfed66e7ca`.
- Its 199 level-2 rule sections are frozen in `tests/golden/vulkanscope_3_0_12_rule_headings.txt` and every section is classified by `tests/golden/vulkanscope_3_0_12_rule_applicability.json` as adopted, adapted, API-specific reference or historical methodology reference. Missing, duplicate, reordered or unclassified sections are release-blocking.

## Registry, query names and evidence
- `registry/gl.xml` remains SHA-256 `b9ca2cfa5c676e901c20d34af3407f1687cde0f1336a5ff7a8974d04c7494ad3`.
- Supplied `registry/egl.xml` remains SHA-256 `3327619123cdaa999400b41a7060180616df42571a0fdd11e9726e026f6d0fb8`.
- Hard-coded GL/EGL names are checked against the locked registries. Fabricated names are release-blocking.
- The unregistered `GL_EXT_fragment_shading_rate_attachment` spelling is removed; query ownership uses registered `GL_EXT_fragment_shading_rate` evidence.
- EGL surface-compression fallback names use the canonical `EGL_SURFACE_COMPRESSION_FIXED_RATE_1BPC_EXT` through `EGL_SURFACE_COMPRESSION_FIXED_RATE_12BPC_EXT` registry tokens.
- Registry membership, runtime extension membership, legal query applicability and returned runtime evidence remain separate states; no UI label may fabricate support.

## Performance
- GL/EGL runtime extension lists are normalized once with sort/unique and repeated membership checks use `std::binary_search`.
- EGLConfig-invariant extension gates are computed once before the per-config loop instead of once per row.
- Performance changes are not allowed to reduce report/query coverage or transform failed/not-applicable queries into fabricated values.

## Common UI and icon parity
- 85 shared semantic icon resources are frozen byte-for-byte to VulkanScope 3.0.12 hashes; OpenGLESScope branding, launcher artwork and color resources are excluded from semantic-icon equality.
- Production primary navigation is four destinations: Overview, OpenGL ES, EGL and Extensions. The unused landscape navigation rail is removed and both orientations use the same bottom-navigation interaction model. Shared VulkanScope 3.0.12 geometry is retained: portrait 310dp × 54dp, 42dp indicator with 8dp horizontal inset; landscape 340dp × 46dp, 35dp indicator with 6dp inset; bottom system gap is 4dp.
- The duplicate/unreachable top-level Info page is removed. Info remains a Settings section together with Reports & Database and Update Preferences.
- Shared header actions, selected-state motion, TV focus, desktop wheel/D-pad navigation and page scroll hints follow the VulkanScope shared interaction contract. VulkanScope's Android 12+ RenderEffect capture path is not copied unguarded because VulkanScope minSdk is 31 while OpenGLESScope retains minSdk 24; platform-incompatible blur must never be introduced at the cost of API 24-30 crashes.
- Search fields only render the leading overflow fade when focused text actually overflows; ordinary first characters are not obscured. Trailing fade remains overflow-dependent.

## File Manager
- The File Manager retains six view modes and six sort modes, persisted selection, canonical breadcrumb navigation, bounded directory handling and canonical shared-storage path validation.
- The old full options-dialog route is removed; the compact View & Sort chooser follows the current common interaction model.
- List and grid modes support mouse-wheel, D-pad/PageUp/PageDown navigation and common scroll hints.

## Encyclopedia and Settings
- Encyclopedia remains entirely local and registry-backed, bounded to 2 MiB/6000 catalog entries, caches the parsed catalog and caps visible results at 250 with shared 25-item paging.
- Runtime, Not enumerated and Reference states are distinct. Large command/token/type families require a bounded query before wide scans.
- Encyclopedia explicitly states the evidence boundary: registry presence is reference metadata and does not prove runtime support.
- Settings does not invent Vulkan-only driver-management functions. API-specific omissions are intentional; shared section/navigation/accessibility quality remains parity-gated.

## Verification
- `tools/verify_2_1_0_quality.py` release-blocks the rules, icon, UI, File Manager, Encyclopedia, registry-name and performance contracts.
- `tools/test_2_1_0_negative_mutations.py` proves representative deliberate defects make the gate fail, including identity drift, duplicate rules roots, linear extension lookup, fabricated names, pager drift, old File Manager options, unbounded Encyclopedia results, lost TV grid navigation and icon mutation.
- `tools/verify_2_1_0_regression_contract.py` prevents unrelated production drift from being hidden by test/rules edits.
- Companion Database 1.0.10 accepts exact OpenGLESScope 2.1.0 / 2100 technicalReport-v5 evidence and independently retains exact 2.0.0 / 2000 historical schema-5 evidence.
