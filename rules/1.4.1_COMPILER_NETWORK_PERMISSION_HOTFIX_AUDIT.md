# OpenGLESScope 1.4.1 compiler and connectivity hotfix audit

- Release: OpenGLESScope 1.4.1 / versionCode 1401
- Immutable predecessor: OpenGLESScope 1.4.0
- Predecessor source ZIP SHA-256: `93360baa07b7df420b8ee9b0bde6a741c281580212a55abde082fb5dc86cce54`
- Companion Database: OpenGLESScope Database 0.9.1, already version-scoped for exact producer 1.4.1 / 1401 with technicalReport schema 4
- Capability/report/schema semantics: unchanged from 1.4.0

## Findings

The predecessor had four release-blocking compiler defects evidenced by the supplied release build log: four unused EGL constants fail native compilation under the mandatory `-Werror` policy, one nullable `String?` value is passed where `CustomMinimumResult` requires `String`, and two `remember` invocations are made from the `LazyListScope` builder rather than composable scope.

The installed build also has a deterministic startup crash path: `hasValidatedInternet` queries `ConnectivityManager.activeNetwork` and `getNetworkCapabilities`, while the manifest declares `INTERNET` but omits the normal `android.permission.ACCESS_NETWORK_STATE` permission. Android therefore throws `SecurityException` before normal activity startup can complete on the affected path.

## Fix boundary

- `app/build.gradle.kts`: release identity only, 1.4.1 / 1401.
- `app/src/main/AndroidManifest.xml`: add `android.permission.ACCESS_NETWORK_STATE`; no dangerous/runtime permission prompt is introduced.
- `app/src/main/cpp/openglesscope.cpp`: remove four unused private constants only; no query, enum mapping, report field or runtime capability behavior is removed.
- `app/src/main/java/com/efishell/openglesscope/MainActivity.kt`: make the scalar minimum-result display value non-null at the call boundary and compute the Raw technicalReport remembered snapshot in composable scope before the `LazyColumn` builder.

## Regression gates

`tools/verify_1_4_1.py` verifies release identity, predecessor hash, manifest permission, Kotlin compile-sensitive source shape, removed unused constants, rules/audit presence and companion-producer alignment. `tools/verify_compile_regressions.py` and `tools/verify_security_contracts.py` independently gate the compiler and permission invariants. `tools/test_1_4_1_negative_mutations.py` proves that permission removal, nullable-argument restoration, unused-constant restoration and the invalid LazyColumn `remember` placement are rejected, while an unrelated changelog-only mutation remains accepted by the targeted gates.

The 1.4.1 regression contract allowlists only the four production files above against exact OpenGLESScope 1.4.0 hashes. Registry snapshots, collection semantics, report schema, Database transport, update verification, ABI policy, UI resources and all other production files remain byte-locked to the predecessor.
