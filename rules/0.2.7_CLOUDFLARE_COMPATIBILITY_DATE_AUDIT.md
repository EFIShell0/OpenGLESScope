# OpenGLESScope Database 0.2.7 — Cloudflare Compatibility-Date Audit

## Finding

The previous release used `compatibility_date: 2026-08-24`. During deployment while Cloudflare still considered 2026-08-23 current, the Workers API rejected the upload with error 10021: compatibility date cannot be in the future.

## Correction

- `worker/wrangler.jsonc` now uses `2026-08-23`, the latest date accepted for the observed deployment window.
- Release audit tooling checks the deployable date instead of advancing from the local Europe/Istanbul calendar alone.
- Application producer contracts, report schemas, normalizers, D1 migrations, stored report hashes and security validation are unchanged.

## Rule

Compatibility dates are runtime opt-in boundaries, not release timestamps. A release must prefer a deployable non-future date over a numerically newer date.
