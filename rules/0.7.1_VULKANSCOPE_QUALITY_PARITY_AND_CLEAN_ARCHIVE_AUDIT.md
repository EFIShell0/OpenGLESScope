# OpenGLESScope 0.7.1 VulkanScope-quality application parity and clean-archive audit

## Scope
OpenGLESScope 0.7.1 was re-audited against VulkanScope's shared application-quality architecture. Only capabilities with a real OpenGL ES/EGL/Android equivalent are carried over. Vulkan-only objects, structures, query semantics and result models are intentionally not synthesized.

## Corrected parity gaps
- Analysis snapshots now preserve the complete current EGL runtime context/binding/pbuffer evidence and EGL Config extension-backed fields, including exact unavailable-attribute errors.
- Limits and query diagnostics are separated so diagnostic rows do not alter implementation-limit totals.
- Formats and shader precision gained bounded searchable presentation.
- EGL runtime presentation is split into identity, current binding/context, collector pbuffer and exact unavailable-attribute evidence.
- Extension details expose the exact implemented query gates and authoritative Khronos registry navigation without inferring support or promotion.
- The Analysis query graph now covers both OpenGL ES and EGL exact query gates.
- The diagnostic evidence heuristic includes explicit EGL current-binding inconsistency.
- Android OS/device provenance was expanded consistently across UI, TXT and HTML.
- Database application metadata now includes installed ABI and Android-supported device ABIs.

## Archive policy
The source release archive contains no README.md, root release.md, dedicated packaged app-store metadata directory or forbidden third-party comparison product naming.

## Evidence semantics
Unknown, Unsupported, Unavailable and Not applicable remain distinct. Missing query evidence is never converted to Unsupported. Vendor names, renderer names, Android build identity and registry references are provenance/presentation only and never create capability claims.

## Release gates
`tools/audit_release.py`, JSON/XML parsing, source-comment prohibition, archive-hygiene checks, reference-floor checks and clean re-extraction verification are mandatory. A full Android build is reported as passing only if Gradle/Android/NDK compilation actually completes.
