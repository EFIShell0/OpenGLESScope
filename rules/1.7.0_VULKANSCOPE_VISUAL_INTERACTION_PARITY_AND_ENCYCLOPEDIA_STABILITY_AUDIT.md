# OpenGLESScope 1.7.0 VulkanScope visual/interaction parity and Encyclopedia stability audit

## Scope
Shared UI geometry, navigation, semantic icons, button placement, menu placement, Material 3 Expressive motion and state handling are aligned to the checked-in VulkanScope 1.4.3 reference where they are API-neutral. OpenGLESScope branding and OpenGL ES/EGL-specific information architecture remain authoritative. Vulkan-only and Turnip-specific concepts are not introduced.

## Shared UI parity
- Top app bar uses the same 48 dp expressive icon-button contract, logo/title placement and Settings action placement.
- Compact navigation bar and navigation rail use the same selection model, icon geometry and expressive click feedback.
- Shared page transitions use directional spring slide/fade motion.
- Settings is an overview of expressive destination cards with dedicated Info, Reports & Database and Update preferences destinations.
- Shared destination cards, section cards, filters, search affordances, scrolling hints and modal/update controls follow the same dark Material 3 Expressive layout language.
- Rotation keeps current primary navigation/settings state and does not trigger capability recollection.

## Encyclopedia stability
- Registry catalog decompression is bounded to 2 MiB and catalog count to 6,000 entries.
- Registry entries are identity-validated, duplicate-rejected and long text fields are bounded before publication to Compose state.
- Catalog loading runs on Dispatchers.IO and failures are surfaced in-page.
- UI filtering is lazy/bounded to 101 collected matches with only 100 rendered entries.
- Commands, tokens and types require at least two search characters before the large family is evaluated.
- Query input is bounded to 160 characters.

## Evidence boundary
Static/source and state-contract checks are not Android runtime evidence. Gradle build/lint/unit remain NOT EXECUTED when Gradle 9.7.1 cannot be obtained in the verification environment.
