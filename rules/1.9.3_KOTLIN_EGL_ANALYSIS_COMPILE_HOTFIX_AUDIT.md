# OpenGLESScope 1.9.3 Kotlin EGL Analysis compile hotfix audit

The supplied 1.9.3 source candidate completed native compilation for arm64-v8a, armeabi-v7a and x86_64 and then failed at `:app:compileReleaseKotlin` with three `Unresolved reference 'runtime'` errors in `MainActivity.kt`.

The affected code is inside the `tech.optJSONObject("eglRuntime")?.let { e -> ... }` Analysis-entry mapping. The three schema-5 query-provenance fields for `surfaceGlColorspaceQuery`, `surfaceVgAlphaFormatQuery` and `surfaceVgColorspaceQuery` must be read from that scoped `JSONObject` receiver `e`. Using `runtime` was a name-resolution defect introduced while adding the expanded EGL surface evidence; it did not describe another valid object.

The correction changes only those three receivers from `runtime` to `e`. Release identity remains 1.9.3 / 1903 because the failed candidate never produced a valid release APK, and Database 1.0.8 remains the exact companion contract for 1.9.3 schema-5 submissions. No GL/EGL collection semantics, schema version, registry snapshot, security contract or UI behavior is otherwise changed.

`verify_1_9_3_compile_hotfix.py` locks the three correct bindings, rejects restoration of the undefined receiver and runs a Kotlin compiler name-resolution probe when `kotlinc` is available. `test_1_9_3_compile_hotfix_negative_mutations.py` restores each defect independently and requires the verifier to fail.
