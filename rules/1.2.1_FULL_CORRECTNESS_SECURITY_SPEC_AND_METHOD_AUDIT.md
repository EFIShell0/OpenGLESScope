# OpenGLESScope 1.2.1 full correctness, security, specification and method audit

## Scope
This audit applies to OpenGLESScope 1.2.1 and uses the VulkanScope 1.4.3 release-method classes where applicable to OpenGL ES/EGL: immutable predecessor locking, locked upstream registry evidence, specification/query regressions, isolated probe lifecycle/terminal ownership, strict report validation, resource ceilings, security, compile-sensitive guards, state models, negative mutations, deterministic packaging and clean-extract re-verification. Vulkan-only concepts are Not applicable rather than imitated with invented OpenGL ES concepts.

## Current specification and registry baseline
- OpenGL ES 3.2; GLSL ES 3.20; EGL 1.5.
- Bundled registry: `registry/gl.xml`.
- Locked SHA-256: `b9ca2cfa5c676e901c20d34af3407f1687cde0f1336a5ff7a8974d04c7494ad3`.
- Manifest census: 3301 commands, 6074 enum entries, 863 registered extensions and 350 GLES extension entries.
- CMake hashes the bundled registry and fails configuration on a hash/sentinel mismatch.

## Correctness findings fixed in 1.2.1
- Corrected four LATC labels from unregistered `_NV` spellings to registered `_EXT` identifiers.
- Removed the unregistered historical `GL_NVIDIA_PLATFORM_BINARY_NV` symbolic display label and fabricated `GL_*` pseudo names for timer-query counter-bit descriptions.
- Removed the desktop-only fragment-shading-rate primitive/multi-viewport state from the GLES path and separated attachment state behind its exact extension dependency.
- Added missing `GL_NV_fbo_color_attachments` and `GL_ARM_shader_core_properties` implementation-dependent state.
- Added bounded supported-rate enumeration for `GL_EXT_fragment_shading_rate`.
- Added OpenGL ES 3.0+ internal-format sample-count evidence with `glGetInternalformativ`; target availability is API/extension gated.
- Added `GL_NV_internalformat_sample_query` detail when advertised and callable; failure remains Unavailable evidence.
- Hardened JNI JSON publication by escaping non-ASCII driver bytes before `NewStringUTF`.

## Query and reporting coverage
The registry-derived gate finds 91 core OpenGL ES 2.0-3.2 capability-shaped `GetPName` states and 34 GLES extension capability-shaped `GetPName` candidates; zero missing is required. The public matrix retains 145 parity rows plus 123 OpenGLESScope additional-query rows, and the 104 minimum/maximum reference requirements remain locked.

Internal-format reporting uses the 41 sized color/depth/stencil-renderable format census. ES 3.0 queries `GL_RENDERBUFFER`; ES 3.1 adds `GL_TEXTURE_2D_MULTISAMPLE`; ES 3.2 adds `GL_TEXTURE_2D_MULTISAMPLE_ARRAY`. Each per-format sample-count result is bounded to 64 entries.

The complete local report schema requires typed `internalFormats` alongside limits, extensions, compressed/binary formats, precision, EGL runtime/configuration and diagnostics. Internal-format evidence is exposed in Formats UI, Analysis, TXT and HTML.

The companion Database is advanced to 0.7.7 with a backward-compatible technicalReport-v3 contract for OpenGLESScope 1.2.1. The v3 object adds the bounded `internalFormats` evidence array while historical technicalReport-v1/v2 producers retain their original closed schemas and validation. OpenGLESScope 1.2.1 therefore transports internal-format evidence end-to-end instead of silently dropping it at Database submission.

## Terminal and lifecycle integrity
- Collection runs in the non-exported isolated `:opengles_probe` process.
- A mutex serializes probe requests.
- Result publication is bounded, temp-written, synced, atomically renamed, structurally validated and only then followed by a service-owned `.done` marker.
- Timeouts, cancellation and stale-process quiescence are explicit.
- Strict JSON grammar rejects duplicate keys, excessive nesting and excessive container counts.
- Incomplete/invalid `status=available` data cannot be promoted to a complete report.

## Resource and memory-safety contract
Explicit limits cover GL enumerations, EGL configurations, program-binary bytes, runtime strings, extension tokens, info logs, internal-format sample counts, JSON depth/items, result bytes, Database payload/response bytes and APK bytes. Static review is not sanitizer/profiler evidence; HWASan/ASan/Perfetto and vendor-driver leak testing are not claimed as PASS unless actually executed.

## Security contract
Cleartext and backup remain disabled; service/provider components remain non-exported; provider paths are restricted. Database submission is explicit, fixed HTTPS origin, redirect-disabled and bounded. Update traffic is confined to the official project GitHub release flow with bounded download and APK package/signature/version checks. Network actions require validated connectivity. Local HTML uses restrictive CSP. Unique device identifiers, account credentials, tokens and private paths are not submitted.

## VulkanScope-method mapping
The aggregate 1.2.1 gate contains independent equivalents of VulkanScope's regression-contract, specification-regression, registry generation/lock, CMake registry lock, compile-regression, probe lifecycle/terminal publication, report semantics/state model, resource/concurrency, security, UI/accessibility, negative mutation and deterministic package reproduction checks. OpenGL ES/EGL-specific state replaces Vulkan-specific capability structures without weakening the evidence method.

## Evidence boundary
Static/source/registry/spec/state-model gates are run from source and clean extraction before release. Android Gradle assemble/lint/unit and real-device visual/TalkBack/TV/vendor-driver/sanitizer execution are recorded separately; unavailable environments are **NOT EXECUTED**, never PASS.

## EGL canonical error completeness

The native EGL error formatter now preserves the canonical `EGL_CONTEXT_LOST` identifier when the platform header exposes it. Unknown values remain raw hexadecimal evidence rather than receiving fabricated specific names.
