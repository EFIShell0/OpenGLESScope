# OpenGLESScope 2.2.0 VulkanScope 3.0.12 visual/interaction parity audit

- Reference: byte-locked VulkanScope 3.0.12 API-neutral UI/interaction methodology.
- Shared header/Application/About branding uses the exact SCOPE wordmark. Full OpenGLESScope artwork remains restricted to app-specific launch/export branding.
- Shared drawable census: 103 common drawable resources are byte-identical to VulkanScope 3.0.12. The remaining common resource differences are launcher/tv branding, accent colors and app theme/style resources permitted by the OpenGLESScope brand boundary.
- Primary navigation is Overview / OpenGL® ES / Display / Extensions. EGL™ is a nested OpenGL® ES destination and is not a primary bottom-navigation item.
- Header, bottom navigation and system-navigation chrome use the same recorded page-backdrop live blur model and coordinated content insets as the VulkanScope reference.
- Capability evidence rows expose long-press, Android TV OK/Enter long-hold, desktop secondary-click actions where applicable, copy/share/watch/Encyclopedia actions and a detailed provenance dialog. ChromeOS/Android-PC secondary click suppression follows the reference behavior.
- Alert/custom dialogs use the OpenGLESScope accent-color outline while preserving VulkanScope geometry/interaction structure.
- User-facing OpenGL® ES, EGL™ and SPIR-V™ display text is normalized in reusable UI components and report HTML labels without rewriting canonical registry tokens or structured report keys.
- Analysis Database lookup uses the same Database-list / Report-ID mode hierarchy, bounded list filtering, localized submitted-time block, exact report-ID evidence and local comparison action structure. OpenGL ES/EGL-specific metadata replaces Vulkan-only driver fields rather than fabricating equivalents.
- Native collection, Khronos registry locks, schema 2 / technicalReport 5, query legality and evidence-state semantics are unchanged from 2.1.4.
