# OpenGLESScope 0.4.1 VulkanScope-quality parity audit

## Scope

0.4.1 applies the current VulkanScope analysis, comparison, evidence-quality, sharing and release-quality principles to OpenGL ES/EGL without importing Vulkan-only API concepts.

## Required parity

- Analysis exposes Compare, Spec minimums, Graph, Quality, Watched, Share and isolated Tests.
- Snapshot evidence is complete for the collected OpenGL ES/EGL/Display datasets, bounded to 8 MiB and 32,768 entries, and is never silently truncated.
- Comparison supports evidence-kind and state filtering and only marks absence as a regression candidate when the relevant runtime enumeration is complete enough to support that conclusion.
- The OpenGL ES 3.2 minimum evaluator uses directly collected values and preserves requirement direction; missing evidence stays Unknown.
- Query dependency visualization is derived from checked-in exact OpenGLESScope extension/query gates. Registry or GPU identity must not fabricate runtime support.
- Evidence quality is based only on explicit diagnostics/safety anomalies and must not be described as conformance, benchmark or driver quality.
- Watched evidence is bounded and supports Matched/Missing inspection.
- Share uses the canonical official Database report hash route and local QR generation. No external QR service is permitted.
- Database POST does not follow redirects. A permalink is retained only after a successful response supplies a canonical 64-hex report ID.
- Isolated self-tests are attributed only when GL_VENDOR, GL_RENDERER and GL_VERSION match the selected report.
- Vulkan-only Image Format Properties2/external-memory tuple concepts are not copied because OpenGL ES has no equivalent query. Existing OpenGL ES count/list/query diagnostics remain the authoritative evidence model.
