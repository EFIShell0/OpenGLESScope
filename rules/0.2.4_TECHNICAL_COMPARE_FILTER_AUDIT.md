# OpenGLESScope Database 0.2.4 — Compare semantic-state audit

## Scope
OpenGLESScope Database 0.2.4 audits Compare presentation against the project state-semantics rules and the VulkanScope quality reference without importing Vulkan-specific capability categories.

## Result
- Plain metadata and scalar values no longer receive synthetic `Available` badges simply because they were reported.
- Missing values still render as `Unknown / Not reported`.
- Limits use their matching query-diagnostic state.
- Shader precision uses its matching precision-query diagnostic state.
- Diagnostics retain their submitted state.
- Wide-color and HDR-type rows retain support/availability semantics because those fields themselves describe state.
- Application/device/driver/GL/EGL identity, ABI text, EGL Config attributes, extension/enumerant membership text and ordinary display scalars render as values without redundant status decoration.
- `Technical differences only` remains enabled by default and continues to remove producer/collection noise without removing Android/ABI/driver/GL/EGL technical evidence.

## Security and data integrity
The change is presentation-only. Stored payloads, schema 2, technicalReport schema 1, raw canonical TXT, report hashing, Worker validation, CORS/CSP policy, D1 access and submission behavior are unchanged.
