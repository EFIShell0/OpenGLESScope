# OpenGLESScope 1.4.0 full correctness, memory/resource, specification and security audit

## Scope
OpenGLESScope 1.4.0 / versionCode 1400 is audited against immutable 1.3.0 production bytes, the locked `gl.xml` and `egl.xml` registries, OpenGL ES 3.2 / GLSL ES 3.20 / EGL 1.5 semantics, and companion OpenGLESScope Database 0.9.0. Vulkan-only domains remain Not applicable.

## Correctness fixes
- Removed illegal interpretation of EGL creation attributes as `eglQueryContext` runtime state and retained exact creation-request provenance.
- Added bounded legal display/device/DMA-BUF/driver-name EGL evidence with object/extension/entry-point gates.
- Added missing QCOM/NV/ARM implementation queries and robustness reset/robust-access state with canonical names and query types.
- Producer report validation now enforces Database-aligned bounds, canonical terminal states and uniqueness.

## Resource and lifetime audit
History metadata no longer decompresses snapshots, history filesystem operations run on `Dispatchers.IO`, large snapshot JSON is not used as a Compose effect key, selected snapshots alone are inflated, and SHA-256 identifies checkpoints. Native diagnostic pointer ownership uses a scoped RAII guard. These are source/lifetime safeguards; no device heap-profiler or sanitizer run is claimed.

## Security and release evidence
Existing fixed HTTPS origin, redirect rejection, 2 MiB Database response/submission limits, update exact-version/hash/signature path, cleartext disablement, isolated non-exported probe process and sensitive-data exclusions remain release-gated. All source gates, negative mutations, deterministic archive reproduction and clean-extract rerun are required. Android build/lint/unit, device, sanitizer and heap-profiler results are recorded separately and are never inferred from source checks.
