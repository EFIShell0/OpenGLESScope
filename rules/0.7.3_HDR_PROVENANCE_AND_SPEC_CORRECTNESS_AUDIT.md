# OpenGLESScope 0.7.3 HDR provenance and specification correctness audit

## Scope
- Android Display/HDR null-versus-empty provenance.
- End-to-end UI, Analysis, TXT, HTML and Database propagation.
- Preservation of current OpenGL ES/EGL query coverage and evidence-state rules.

## Correction
- API 34+ uses current `Display.Mode.supportedHdrTypes`; a filtered empty list is Unavailable.
- API 24-33 keeps a null `Display.hdrCapabilities` object as Unknown/not exposed and distinguishes it from a non-null object with an empty supported-types array.
- `hdrCapabilityStatus` is now explicit in both Database display objects and canonical reports.
- Unknown Android HDR integer values remain raw `Android HDR type N` evidence.

## Preserved contracts
- OpenGL ES 3.2 / GLSL ES 3.20 / EGL 1.5.
- 145/145 public capability floor, 49 additional implementation queries and 104 spec minimum/maximum checks.
- Schema 2 / technicalReport 2, explicit all-or-nothing submission, probe isolation and three release ABIs.
