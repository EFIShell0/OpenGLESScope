# OpenGLESScope 1.5.0 full report and updater-security quality audit

Predecessor: final OpenGLESScope 1.4.1.

## Verified defects corrected
- Info exposed stale `technical report 2` text although the canonical report contract was technicalReport schema 4.
- TXT/HTML reporting dropped collected EGL pbuffer mipmap/multisample evidence; TXT also dropped four EGL Config evidence classes already present in UI/technicalReport.
- Automatic redirects were enabled on the update clients while the release security contract required no automatic redirects; the old source gate passed only because an unrelated Database client contained `followRedirects(false)`.
- Stable update discovery did not exclude GitHub prereleases.
- Abandoned update `.apk`/`.part` cache files could survive process death until cache eviction.

## Corrections
Shared schema constants drive UI and serialization; TXT/HTML report surfaces preserve the complete EGL evidence listed above. Update metadata/download clients disable automatic redirects; asset redirects are manually bounded and restricted to HTTPS GitHub release infrastructure. Optional GitHub SHA-256 asset metadata is verified before Android package/signature checks. Stable discovery excludes drafts/prereleases and stale updater cache artifacts are cleared at startup.

## Evidence boundary
No RAM leak was claimed without heap-profiler evidence. Existing lifecycle/resource/History gates remain mandatory and no new unbounded collection was introduced. Real Android compile/lint/unit and device/runtime evidence are separate execution classes.
