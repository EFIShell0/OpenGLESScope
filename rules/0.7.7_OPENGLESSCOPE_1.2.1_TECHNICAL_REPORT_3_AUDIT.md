# OpenGLESScope Database 0.7.7 OpenGLESScope 1.2.1 technicalReport-v3 audit

This release closes the producer and report-loss gap identified while auditing OpenGLESScope 1.2.1 against the VulkanScope evidence method. Database 0.7.6 rejected 1.x producers and its closed technicalReport-v2 schema could not carry the new `internalFormats` runtime evidence.

0.7.7 keeps top-level schema 2, retains historical technicalReport v1/v2 contracts, and adds technicalReport v3 for OpenGLESScope 1.2.1 / 1201. V3 adds bounded internal-format rows with exact target/format identity, evidence state, sample counts and optional NV sample properties. Worker validation rejects malformed types, duplicate target/format rows, duplicate/non-positive sample counts, mismatched NV sample rows, missing matching diagnostics, wrong producer identity and unsupported future producers.

The frontend normalizer, Formats page, per-report Formats detail and Compare field map retain v3 evidence. No GPU-name, extension-string or registry-presence inference is introduced.

The release gate must run source audit, Worker contract tests, route/Compare/Statistics/UI tests, JSON/Node/Python syntax checks, package allow-list/hygiene, deterministic archive reproduction and clean-extract reruns. Cloudflare production deployment is not claimed by these local gates.
