# OpenGLESScope Database 0.1.19 full database audit

Audited baseline: OpenGLESScope Database 0.1.18, with VulkanScope Database 0.35.6 used as the quality/security reference and OpenGLESScope 0.1.23 used as the current producer compatibility target.

## Correctness fixes

- Fixed current-producer submission compatibility: OpenGLESScope 0.1.23 uses the `OpenGLESScope report` TXT header rather than the older `OpenGLESScope <version>` first line. The Worker now accepts the current header, validates its application version/versionCode/package lines against the structured payload, and retains the compatible legacy header path for 0.1.17+.
- Enforced exact JSON object shapes instead of accepting undeclared fields in nested submission objects.
- Enforced complete top-level and technical-report display evidence and required the duplicated display objects to match exactly.
- Restricted query diagnostic state to the four producer states: Available, Unavailable, Not applicable and Unknown.
- Corrected limit aggregation so diagnostics are authoritative, missing evidence contributes Unknown, every loaded report is included in the denominator, and contradictory unavailable/unknown queries do not contribute a displayed aggregate value.
- Corrected diagnostic coverage so absent diagnostics contribute Unknown rather than disappearing from the denominator.
- Corrected Android HDR semantics: an explicit empty `hdrTypes` array is Unavailable; missing evidence is Unknown; neither state is converted into Unsupported.
- Corrected the report-detail parsed OpenGL ES version presentation from a spaced separator to canonical `major.minor` form.

## Security and privacy hardening

- Sensitive JSON field-name normalization now removes punctuation and separators before comparison, preventing variants such as `user_id`, `account-id` or `access.token` from bypassing forbidden-field matching.
- Existing 2 MiB streamed request-body enforcement, exact `application/json` media type handling, recursive nesting bound, SHA-256 stable canonical deduplication, D1 parameter binding, cursor validation, CORS restriction and no-request-IP-storage behavior remain in force.
- Malformed stored JSON continues to produce a generic server error without stack disclosure.
- Production Cloudflare account and D1 IDs remain fail-closed pinned, and Wrangler remains pinned to 4.124.0.
- The public submission endpoint intentionally has no user account/authentication dependency. This does not cryptographically prove that an arbitrary non-browser caller is the official APK; production edge rate limiting/abuse controls remain an operational responsibility without persisting request IP data in report records.

## Branding integrity

- Rebuilt the white EGL web artwork directly from the current OpenGLESScope 0.1.23 official EGL asset by preserving the source alpha geometry exactly and changing only the visible RGB to white. The cache-busted asset is `egl-logo-white-v029.png`.
- The GL|ES artwork remains pixel-identical to the current application `ic_opengles_gl_es.png`.

## Performance and reliability

- Structured report-detail responses no longer duplicate the full technical payload into a second `normalized` object. Compatibility normalization is returned only for legacy rows without structured `technicalReport`, reducing response size and frontend memory pressure.
- Removed the misleading empty static-index fallback for live API failures. API/configuration failure is now shown explicitly instead of appearing as a valid empty database.
- Detail-fetch failures are counted and visibly surfaced rather than silently omitted.
- Technical global search now searches loaded structured technical fields as advertised by the UI.
- OpenGL ES/EGL overview detail membership uses report-ID sets instead of repeated quadratic scans.
- Main-view transitions now cancel stale animations, expose `aria-busy`, use transform/opacity animation and honor reduced-motion preference.

## Schema and validation parity

- `report.schema.json` now matches Worker bounds for implementation limits and query diagnostics.
- Technical-report display fields are explicitly required in the JSON schema.
- Precision scalar strings and EGL config string IDs are bounded.
- Diagnostic status enumeration is explicit in the JSON schema.
- Compatibility floor is represented as versionCode 117+ while Worker also validates the `0.1.<patch>` producer patch floor.

## Deployment pipeline hardening

- GitHub Pages now validates `data/index.json` and runs the full repository audit in a build job before the Pages artifact is uploaded.
- Pages workflow action versions are aligned with the current reference-quality deployment family (`checkout@v6`, `setup-python@v6`, `upload-pages-artifact@v4`, `deploy-pages@v4`).
- `cancel-in-progress` is disabled for the Pages deployment group so a newer push does not abort a production deployment already in progress.
