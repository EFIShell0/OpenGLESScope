# OpenGLESScope Database 0.1.26 Full UI, Security and Specification Audit

## Scope
This release audits the complete database source inherited from 0.1.25, compares shared table/scroll behavior against VulkanScope Database 0.35.8, and rechecks the public Khronos OpenGL ES and EGL registries as of 2026-08-21.

## Corrected defects
- Replaced the SVG-based custom table scroll track introduced in 0.1.25 with the same HTML track/thumb model used by the VulkanScope reference. The SVG coordinate system did not reliably equal the rendered CSS-pixel track width, which could leave the thumb visually short of the right endpoint.
- Clamped scroll position, thumb width and thumb travel to the real rendered track dimensions. The right endpoint now maps to the exact maximum thumb translation.
- Applied the reference neutral sticky table-header surface, typography and cell geometry globally rather than only to the Reports table. This removes the remaining visual mismatch in Display/HDR and other tabular destinations.
- Removed source CSS comments and an accidental literal escaped newline sequence that violated PROJECT_RULES and caused the 0.1.25 audit to fail.

## Specification review
- Khronos still identifies OpenGL ES 3.2 as the current OpenGL ES API version.
- Khronos still identifies GLSL ES 3.20 as the current OpenGL ES shading-language version.
- Khronos still identifies EGL 1.5 as the current EGL core API version.
- The database keeps runtime implementation strings separate from these published baselines and does not infer capability from GPU/vendor/Android marketing identity.

## Security and correctness review
- Frontend CSP remains same-origin except for the configured HTTPS Worker API connection.
- No third-party JavaScript, analytics or remote fonts are introduced.
- Dynamic report content continues to pass through escaping before HTML presentation; raw report text remains text content rather than executable markup.
- Worker submission size remains bounded to 2 MiB and frontend JSON materialization remains bounded to 4 MiB with timeout protection.
- D1 statements remain parameterized for cursor and report-ID queries.
- Report IDs and cursors retain strict format validation.
- Recursive sensitive-field detection and nesting bounds remain enabled.
- API responses retain restrictive CORS/security headers and production deployment remains pinned to the OpenGLESScope Cloudflare account and D1 database.
- No schema or D1 migration is required by this release.

## Version separation
Database 0.1.26 does not invent an OpenGLESScope 0.1.26 producer. The current producer metadata remains OpenGLESScope 0.1.25 while compatible 0.1.x submissions continue to follow the existing compatibility policy.
