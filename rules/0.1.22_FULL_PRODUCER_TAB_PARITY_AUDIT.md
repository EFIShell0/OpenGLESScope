# OpenGLESScope Database 0.1.22 Full Producer and Tab Parity Audit

## Inputs
- OpenGLESScope Database 0.1.21
- OpenGLESScope 0.1.25
- VulkanScope Database 0.35.8 shared quality reference
- Khronos OpenGL ES Registry and EGL Registry audited 2026-08-21

## Producer compatibility
OpenGLESScope 0.1.25 keeps submission schema 2 and technicalReport schema 1. The database therefore retains the 0.1.17+ compatibility floor while treating 0.1.25 as the current producer audit target. ABI remains canonical-TXT-derived read metadata because the current structured application object does not contain ABI fields.

The 0.1.25 producer adds KHR_debug extension-gated/core debug limits and EXT_disjoint_timer_query query-counter-bit evidence. The Worker validates the corresponding diagnostics without inferring capability from GPU identity or registry presence.

## Main-view audit

### Reports
- Server-authored submission timestamp remains first and deterministic.
- GPU, vendor, Driver, OpenGL ES, EGL, Android, producer version, ABI and report ID remain visible.
- Sorting includes driver, runtime versions, GPU/vendor, Android, producer version and submission time.
- Filtering precedes pagination and no more than 50 rows are rendered.

### OpenGL ES
- Runtime OpenGL ES and GLSL ES distributions remain separate.
- Exact implementation strings are preserved.

### EGL
- EGL initialized version, vendor and client API evidence remain distinct.
- EGL runtime identity is not reinterpreted as OpenGL ES capability.

### Extensions
- OpenGL ES, EGL display and EGL client scopes remain separate.
- Enumeration diagnostics are authoritative.
- A successfully enumerated absent token is Not listed.
- An unavailable enumeration cannot be presented as Not listed or Unsupported.

### Limits
- The universe contains only real GL implementation-limit query names and their matching diagnostics.
- EGL identity, GL identity, extension enumeration, runtime-format enumeration and shader-precision diagnostics are excluded from the limit universe.
- Every loaded report contributes Available, Unavailable, Not applicable or Unknown to the denominator.

### Formats
- Compressed texture, shader binary and program binary families remain separate.
- Enumeration diagnostics determine whether a missing token means Not listed, Unavailable, Not applicable or Unknown.

### Precision
- Vertex/fragment shader stages retain exact range and precision values.
- Failed or missing precision queries remain in the all-loaded-report denominator through diagnostic evidence.

### EGL Configs
- Every current structured EGL configuration attribute remains accessible in report detail.
- Main view preserves report identity, config count, EGL vendor and initialized EGL version.

### Display & HDR
- Android display evidence remains separate from GL/EGL capability.
- Current mode, refresh, supported-mode count, wide-color evidence, HDR types and Android luminance metadata are visible.
- Unknown HDR names remain text and artwork is used only for recognized submitted names.

### Diagnostics
- Available, Unavailable, Not applicable and Unknown remain distinct.
- Missing report evidence contributes Unknown rather than disappearing from the denominator.

### Compare
- Comparison uses exact report values.
- Application/ABI, device/Android, driver, OpenGL ES, EGL, limits, extensions, formats, precision, diagnostics, EGL configs and display evidence remain comparable.
- Missing values are not synthesized.

## Report-detail audit
- Summary, OpenGL ES, EGL, Extensions, Limits, Formats, Precision, EGL Configs, Display/HDR, Diagnostics and Raw report remain visible even when empty.
- Category counts are displayed in detail tabs where a natural count exists.
- Extensions and Formats show enumeration-query evidence.
- Limits and Precision display value and diagnostic state together.
- Raw report remains canonical TXT and is never replaced by normalized data.

## Responsive and interaction audit
- Every wide table uses the same synchronized native-scroll, arrow, drag-track, keyboard and edge-shadow behavior.
- Custom scrollbar thumb width and offset derive from actual scroll geometry.
- Coverage meters and custom scrollbar geometry do not require CSP-blocked inline style attributes.
- Reduced-motion preference removes nonessential motion without removing function.
- Main navigation and detail tabs retain keyboard and bring-into-view behavior.

## Worker and security audit
- Current OpenGLESScope 0.1.25 canonical identity and section counts are cross-checked with structured data.
- Duplicate current-producer limits, diagnostics, extension tokens, runtime formats, precision keys and EGL config IDs are rejected.
- Available structured limit and precision values require matching Available diagnostics.
- Non-empty extension/format arrays require successful enumeration evidence.
- OpenGL ES 3.2 / KHR_debug and EXT_disjoint_timer_query evidence is checked when applicable.
- Exact schema shapes, 2 MiB body bound, recursion bound, sensitive-key canonicalization, parameter-bound D1, canonical SHA-256 IDs and server-authored timestamps remain mandatory.
- CORS remains configured-origin-only for browsers and native no-Origin requests remain supported.
- API preflight receives the normal security-header set.
- No D1 migration or stored-report rewrite is required.

## Specification provenance
- Current OpenGL ES core version remains OpenGL ES 3.2.
- Current GLSL ES version remains GLSL ES 3.20.
- Current EGL core version remains EGL 1.5.
- Registry freshness does not create capability evidence; runtime tokens and query results remain authoritative.

## Result
After 0.1.22 changes, no known shared-quality gap remains against VulkanScope Database 0.35.8 in the interaction, evidence-state, responsive-table, report-detail, error-handling or Worker-hardening behaviors that apply to both databases. Domain-specific Vulkan categories are intentionally absent.
