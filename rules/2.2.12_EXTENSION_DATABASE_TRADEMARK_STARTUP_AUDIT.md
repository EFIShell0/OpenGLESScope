# OpenGLESScope 2.2.12 source audit

Reference: byte-locked VulkanScope 3.0.12 production source, Extension Explorer Details, Database submission in Settings, Analysis Diagnostics and provided 10.45-second VulkanScope Database capture (2026-10-01).

- Extension Details: Vulkan reference uses one contained `Open Khronos specification` control following technical evidence, not four extra quick-action blocks. OpenGLESScope keeps long-press actions on the originating token via the existing common `CapabilityKeyValue` component, but no longer duplicates them inside Details. GL/EGL evidence remains authoritative and can differ in number of fields.
- Database: reference video shows transient action row in pending/accepted states, persistent compatibility notice, single status line, report ID and transient copy, full-width Open report on accepted response. The redundant second animated state card is removed. Failure log remains explicit and does not count as success.
- Branding: OpenGL® ES™ appears in headings and displayed labels; raw runtime strings, Khronos registry token names and serialized report evidence remain exact.
- Analysis: monotonic cold Activity-start → opening gate measured separately; format `%.3f s (%d ms)` copied from the reference's `AdvancedAnalysis.kt`. Timing is not saved into technical report schema and remains unavailable after configuration-only recreation.
- Unchanged: native query and EGL legality, registry assets and manifests, report schemas, Android permissions, SDK 37.2 and deterministic packaging.
- Static quality gates and negative mutations are source-level evidence, not equivalent to a verified APK build or real GPU/Android TV execution.
