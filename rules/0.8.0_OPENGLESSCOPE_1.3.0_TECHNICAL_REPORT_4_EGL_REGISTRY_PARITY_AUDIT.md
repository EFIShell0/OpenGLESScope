# OpenGLESScope Database 0.8.0 audit

## Release identity
- Database: 0.8.0
- Current producer: OpenGLESScope 1.3.0 / versionCode 1300
- Submission schema: 2
- technicalReport schema: 4
- Normalizer: 12

## Contract
OpenGLESScope 1.3.0 technicalReport-v4 adds bounded `eglCapabilities` evidence while retaining `eglRuntime`, `internalFormats`, exact runtime extension enumerations, limits, precision, diagnostics, EGL configurations and display evidence. The Worker rejects unknown fields, duplicate capability names, non-canonical evidence states, oversized arrays/strings and producer/schema identity mismatches.

## EGL evidence semantics
Registry/reference presence is never converted into runtime support. `Available`, `Unavailable`, `Not applicable` and `Unknown` remain distinct. Pbuffer-only collection does not claim window-surface presentation evidence. Persistent device identifiers and raw EGL handles are not accepted as capability evidence.

## Backward compatibility
Historical accepted producers remain supported through OpenGLESScope 1.2.1. technicalReport v1, v2 and v3 validation remains version-scoped; 1.3.0 requires v4.

## Security and bounds
The existing 2 MiB body/report bound, fixed allowed origin, no redirects in the producer, canonical stable hashing, sensitive-key rejection, closed schemas, nesting bound, D1 identity pin and security response headers are retained.

## UI and Compare
`eglCapabilities` is preserved in raw report storage, normalized data, EGL overview/detail presentation, global search and exact report Compare without inferring missing values.

## Release gate
Source audit, Worker contract tests including malformed/duplicate v4 evidence, route/Compare/Statistics/UI parity tests, Pages artifact audit, package hygiene and deterministic ZIP reproduction must pass from both the source tree and clean extraction. No runtime/device claim is promoted from static validation alone.
