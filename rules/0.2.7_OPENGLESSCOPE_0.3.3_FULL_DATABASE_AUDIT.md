# OpenGLESScope Database 0.2.7 — OpenGLESScope 0.3.3 Full Database Audit

Date: 2026-08-24

## Scope

This audit compares the Database against OpenGLESScope 0.3.3 / versionCode 303 under the project rules, current OpenGL ES 3.2, GLSL ES 3.20 and EGL 1.5 baselines, canonical TXT evidence, structured technicalReport evidence, Worker validation, frontend normalization, privacy/security bounds and stored-report compatibility.

## Compatibility defect fixed

Database 0.2.5 required the historical canonical TXT line `Parsed core version:`. OpenGLESScope 0.3.3 intentionally replaced that presentation with `Core version:` and `Core version provenance:` so direct GL_MAJOR_VERSION / GL_MINOR_VERSION evidence is distinguishable from GL_VERSION parsing. The old Worker therefore rejected an otherwise valid 0.3.3 complete report.

Database 0.2.7 accepts the exact 0.3.3 evidence and preserves the historical line requirement for older compatible producers. No evidence is inferred and no stored report is rewritten.

## Producer identity

- Current producer: OpenGLESScope 0.3.3.
- Current versionCode: 303.
- Compatible producer floor remains OpenGLESScope 0.1.17 within canonical compatible 0.x releases.
- Current version/versionCode mismatch is rejected.
- Schema remains submission schema 2 and technicalReport schema 1.

## Reporting parity

The structured report continues to retain limits, OpenGL ES extensions, EGL display/client extensions, compressed formats, shader/program binary formats, shader precision, EGL Configs, Display/HDR and query diagnostics. OpenGLESScope 0.3.3's additional count/array query-diagnostic records fit the existing bounded queryDiagnostics array and are available to the Diagnostics and evidence views without a schema migration.

Canonical TXT remains retained as independent evidence. Structured normalization supplements it and does not replace it.

## Security and data integrity

- 2 MiB request body bound remains enforced.
- JSON nesting is bounded.
- Sensitive identifier classes remain recursively rejected.
- Request IP is not persisted as report data.
- D1 access remains parameterized.
- CORS remains restricted to the configured public origin while native Android submissions without browser Origin remain supported.
- Report IDs remain SHA-256 of stable canonical JSON.
- Existing CSP and response hardening remain unchanged.
- No background report submission is introduced.

## Platform metadata

Android security patch, ABI and supported ABI evidence remain validated as explicit submitted data. Display/HDR luminance values remain Android-reported metadata and are not treated as measured physical panel capability.

## Database storage

No D1 migration is required. Database 0.2.7 changes validation and release metadata only; existing reports, hashes and canonical report text are not mutated.
