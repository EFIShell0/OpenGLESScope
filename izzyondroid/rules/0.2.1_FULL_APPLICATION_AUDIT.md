# OpenGLESScope 0.2.1 Full Application Audit

OpenGLESScope 0.2.1 was audited against OpenGL ES 3.2, GLSL ES 3.20, EGL 1.5, current Android Display/HDR API semantics and OpenGLESScope Database 0.1.26.

The current Khronos core baselines remain OpenGL ES 3.2, GLSL ES 3.20 and EGL 1.5. Runtime strings, exact extension tokens and implementation queries remain authoritative over GPU/device naming.

HDR desired minimum, desired maximum and desired maximum-average luminance are displayed in cd/m² in the application UI, canonical TXT and self-contained HTML. The structured Database payload preserves the corresponding values as numeric luminance fields. Android HDR_TYPE_INVALID is now filtered on all supported API levels rather than only the API-34+ mode-specific path.

Display listener refresh work was tightened so unrelated display-added/display-changed callbacks do not unnecessarily refresh the activity display snapshot. Listener registration remains paired with unregister in DisposableEffect.

Static lifecycle/resource review found the DisplayManager listener is disposed, OkHttp responses and streams use scoped close/use blocks, the native-probe ExecutorService is shutdown on service destruction, probe files are removed in finally, and EGL context/surface/display resources are released on normal and failure exits. No known retained-reference or unbounded in-process collection path was found in the audited source.

TXT, HTML and Database payload paths retain runtime OpenGL ES/EGL identity, limits, exact OpenGL ES/EGL extension lists, compressed/shader/program formats, shader precision, query diagnostics, EGL configurations and Android Display/HDR evidence. No collected dataset is intentionally dropped from one export path.

Database 0.1.26 remains structurally schema-v2 / technicalReport-v1 compatible with the 0.2.1 payload shape, but its Worker and JSON Schema explicitly accept only 0.1.x application versions. Therefore a truthful OpenGLESScope 0.2.1 submission is rejected by Database 0.1.26 until the Database producer-version gate is updated. OpenGLESScope 0.2.1 does not falsify its version to bypass that rule.

A complete Android build/lint run is not claimed from this environment because the Gradle 9.7 distribution is not locally cached and network download of services.gradle.org is unavailable. Static release audit, source-integrity checks and ZIP integrity are performed instead.
